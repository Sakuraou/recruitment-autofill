# 当前项目内的动态字段

v0.6.8 在连续项目流程增加有界联动。选择原生下拉或单选后，网页可能展开新问题；新问题经过新的观察和规划，再读取同一条本地项目。动态联动不能跳过最终完整核验。

## 观察与规划

旧字段集合仍必须全部通过回读，原节点、编辑器、列表、已有卡片和动作按钮保持连续。新捕获必须是同一运行的相邻版本，档案修订相同、编辑器仍处于新增状态，字段集合只能严格扩大。减少或替换字段、改变动作或替换节点不属于当前能力。

规划器消费原 populate-editor 计划和事务，签发仍为 add-invoked 的新草稿事务。它保留同一项目索引和事务标识，不授予 Save 或第二次 Add。新草稿绑定捕获的编辑器、字段集合、编辑器修订和档案修订；原事务、克隆和旧计划不能重用。

最多允许两次展开，即三轮字段填写。超过范围时停止保存并报告，不能把上限当成“已完成”。只有新的完整字段集合通过原 FieldsVerifiedReceipt，才进入正常的保存规划和保存后身份核验。

## 语义和本地值

新字段用新扫描引用识别。已经成功写入的陌生字段，其含义只在本次记录的原 DOM 节点上暂存；不同项目开始时清空。它不包含答案、不跨记录复用、不写浏览器存储。每轮仍从当前项目重新取值、执行相同格式检查并保留网页已有正确值。

模型仍只理解白名单含义，不返回答案、项目索引、选择器或点击动作。先检查所有字段的本地事实，再整批识别真正未知的字段；缺少事实或模型回答不完整时不写入新一轮。页面在轮次之间或模型等待期间改变时，先前的含义也不能用来继续填写。

## 稳定检测和边界

实际写入原生选择控件后，在当前编辑器等待 750ms 静默窗口，总时限为三秒。原值或控件含义在等待期间被改写、节点替换、用户停止或无法稳定时，不签发后续规划。未改动的选择控件不会重复触发 change。文本输入触发的同步新字段也会在回扫时被发现；任意长的异步更新以及仅文本触发的延迟新字段尚未保证。

此功能目前用于主文档中唯一且可验证的通用项目列表。项目自定义 ARIA/移动组件、字段替换或收缩、其他通用重复栏目、截图后备和自主按钮探索仍待后续迭代。中国移动已有专用流程保留。

## 验证

先用旧流程复现“项目角色选择后新增技术栈即停止”。18 项规划契约专项和 11 项项目流程新增专项验证原回执仍拒绝新增字段、草稿凭据消费/修订/范围/上限，以及延迟展开、陌生字段复用、缺事实、手改、节点/按钮/选项变化和停止。

隔离的实际生产 MV3 通过本机服务和虚构模型验证两次 600ms 延迟展开、三个独立语义批次、只新增和保存一次、暂停重开恢复、后续模型等待时手改，以及第四轮上限。未访问真实招聘网站或真实云模型；完整回归结果以 VERIFICATION.md 为准。
