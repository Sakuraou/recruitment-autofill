# 教育和项目的卡片标题身份

状态：verified（2026-10-04，生产 v0.6.24）；隔离 DOM 探针已复现。实习的同类修复已在 v0.6.22 完整验收。

## 证据与问题

已有教育卡片以“本科”为 h3、段落明确学历／专业，却没有学校标签；已有项目卡片以“开发成员”为 h3、段落描述与来源项目一致，却没有项目名称标签。两个读者把标题直接当成学校／项目名，判 different，随后各点击 Add 一次。探针随后因简化编辑器停止，Add 已发生；不能把后续停止当作防重复成功。

## 身份契约

- 明确学校／项目名称标签是主证据，可以独立区分来源外的另一名称；冲突标签保持不确定。
- 未标注标题只在严格、完整、有界、身份唯一的当前来源集合中核对学校／项目原文后使用。学历、专业、岗位、公司或通用文字不能仅因是 h3 就证明不同条。
- 学校／项目名称与来源中的其他意义同名时，未标注标题保留歧义；明确名称标签可以解决这种歧义。已核对的标题与明确名称冲突，不能选择其中一个。
- 私有快照保存名称证据，共享图、结果、日志和模型不包含个人值。修改 DOM、源资料、列表或编辑器后必须重新捕获。
- 保留教育独立阶段顺序、项目源顺序、同校不同专业／阶段、同名不同日期、进行中状态与保存核验。不降低已有动作和回读保护。
- 项目卡片位于外层申请 form 中时，应读取卡片内可见摘要，仍排除卡片内部编辑表单、隐藏／截断／其他卡片和过量文本。

## 执行提示词

先完成 I-009 原生单选归属。将以上两次 Add 的隔离探针转成纯身份与真实会话失败测试，要求添加前待办、Add/Save 均零；为明确名称加学历／岗位标题补可正常去重、只补下一条、重启不重复的正例。当前完整来源集合只供私有名称核对，不传索引、选择器或动作。项目复用现有有界卡片摘要读取器，并验证外层 form 与内部编辑表单的区别。专项、实际生产 MV3 和完整回归后更新计划及安装版本，再回到实习证明组、存在性分支和当前条模型。

## 当前实施与验收

已实现标题与明确名称标签分离、严格完整来源集合核对，以及跨条目专业／学位／岗位／公司同名歧义保护。教育、项目驱动在捕获与规划时均提供当前完整来源集合；摘要和值留在私有快照里。项目复用有界 recordSummaryText，允许外层申请 form，排除卡片内部编辑器和截断祖先。

43 项初始失败（含六个会话在身份不明确时实际 Add）已复现；49 项新增，第一批六文件 223 项相关通过，补充跨来源歧义与异常直接调用后，三个纯身份文件 100 项通过。隔离 Chromium 身份读取 22 项、真实 MV3 项目 14 项／教育 11 项专项通过，新增十个生产标题场景验证添加前停止及明确名称时仅补缺项、源顺序与重启零重复。完整质量重跑 81 文件 2029 项与完整 E2E 16 组 262 项通过；首轮工作进程异常未计通过，最终恢复生产 v0.6.24。

浏览器专项最初的内部 form 负例由嵌套 HTML 字符串生成，浏览器忽略内层 form，实际没有编辑器。改为网站脚本也可创建的真实 DOM form，先断言该节点存在，原有 insufficient／零动作断言保持；重新运行通过。
