# 教育完整集合的最高标记 · I-007E1

状态：verified。42 项新增、三文件 94 项相关、完整 check 67 文件 1541 项、lint、strict 类型检查和构建通过。模块未接页面或模型，生产脚本哈希不变，v0.6.16 浏览器验收沿用 I-007D2；生产当前记录取值器暂时仍拒绝最高标记。

## 目标

分别计算最高学历、最高学位和全日制最高学历。学历来自 level，学位只来自明确 degree，学习形式只来自明确 studyMode；三者不能互相代替。采用完整可信教育投影，不依据当前新增顺序、时间先后、数组首尾、模型判断或单条记录。

先做纯模块和失败测试，不改用户档案、不接页面动作、不扩展模型路径。后续独立验收当前事务的最高标记格式化及生产填写。

## 事实与不确定性

- 集合须通过现有严格投影校验，ID 唯一，记录数有界，不改变源顺序或对象。缺少或无效集合不提供最高答案。
- 学历等级使用专科、本科、硕士研究生、博士研究生的固定顺序。“其他”没有已知等级，不能当作最低。
- 学位有独立等级，只有明确且支持的学士、硕士、博士名称提供等级。缺学位、陌生学位名、否定或预期取得的表述不提供等级；明确“无”与未填分开。不能从硕士学历补成硕士学位，也不能因某条高学历没学位就把本科学位认作最高。
- 全日制最高学历只比较明确全日制记录，明确非全日制排除。未知学习形式不能当作非全日制，招生类型“统招”不能代替学习形式。
- 若最高候选不唯一，摘要中共同的最高学历值可以是确定的，但不能默认最后一条或用日期选出最高记录。最高标记的唯一“是”需要唯一候选；明确低于已知最高的记录可判“否”，最高同级候选保留歧义。未知资料可能改变最高时，不给该维度布尔答案。
- 全部明确“无学位”或全部明确非全日制时，该维度没有最高候选，所有记录的相应最高标记可明确为“否”；空集合和未知资料不属于这一情况。
- 这里的“最高”只比较档案明确填写的事实，不声明学位已获得。问题包含“已取得／已获得／已毕业”时，目前缺少取得状态事实，保持待办；不能从结束日期、在读学历或系统日期推断。
- 各维度独立：学习形式缺失不阻止明确最高学历的纯结果，学历未知也不能推断未知学位。执行层若某必填最高问题无法解决，仍保持整条预检不写入。

## 验收

虚构硕士在数组前、本科在后，分别最高学历及最高学位；本科不是最高，排序或开始日期不改变结果。覆盖博士记录仅有硕士学位、多个同级最高记录、缺学位、明确无学位、未知阶段、未知学习形式、全日制本科与非全日制硕士、全部非全日制、无记录、重复 ID、克隆/冻结输入、不支持名称、否定与预期表述。纯模块无 DOM、无模型、无存储、无网络和个人值日志。

执行提示词：阅读本契约、educationProjection、educationFillOrder、educationFieldResolver 和 workflow/model。先写完整集合最高的失败测试，建立独立有限等级解析及各维度结果；保留未知、明确无和并列的区别，不选第一条或最后一条，不改原投影。最高学位不能沿用学历等级，统招不能充当全日制；已取得问题暂时拒绝。专项与全量检查通过后提交纯模块，再为当前记录最高布尔建立独立事务及格式化契约，最后才接生产流程。
