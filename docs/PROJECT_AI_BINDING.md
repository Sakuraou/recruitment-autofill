# AI 字段含义与当前项目

此能力尚在设计阶段，未接入生产。现有规则项目连续流程可以逐条新增和保存；遇到规则不认识的字段会保留草稿并停下。普通 AI 入口虽然可以理解项目字段含义，但没有当前记录规划的凭据时不读取任何一条项目。

## 下一轮：只做当前项目取值契约

模型继续只返回白名单路径，例如 `projects.description`，不能返回记录索引、项目名称答案、控件选择器或动作。当前具体项目只来自本地记录规划器已签发的 populate-editor 步骤和活动事务。不是按页面第几个输入框推测，也不是默认档案第一条。

建立私有上下文，签发与使用时均检查：

- 运行上下文仍活动、原始 capture/plan/transaction 均有效，没有被消费、停止或替换。
- 捕获是该运行的最新观察，档案和编辑器修订未变；字段集合与已观察的当前编辑器完全对应。
- 规划器的 intentIndex 在本地档案内有效，项目 ID 不重复；所有候选均属于这次 populate-editor 的字段范围。
- 语义绑定仍为原始本地凭据，当前扫描和档案未变；克隆/JSON/伪造对象没有效力。

私有上下文对外只显示记录类型，不暴露个人答案或项目索引。具体值在本地由当前项目读取。日期精度、进行中、字数、URL、选项唯一匹配和控件格式沿用项目规则的共同校验。缺值不生成答案、超长不截断、模糊选项不提供可写值；保持模型来源与候选状态。

先通过两个项目不同名称/简介且规划第二条的测试，证明读取第二条；再覆盖无上下文、上下文克隆、消费/停止/新 capture、编辑器变化、同修订号内容变化、越范围绑定及日期/选项边界。此层只产生候选，不能写 DOM 或签发保存权限。

## 后续：接入记录流程

只在已授权项目任务的当前编辑器存在真正语义缺口时调用模型；已认识但缺事实、日期精度不足或协议字段不调用。未知字段应先整批理解和本地校验，全部必填项可处理后才进入原绑定器写入，保留原子写入、回读、回滚和保存后记录身份核验。

内容脚本继续只获取最小项目投影。提供方通过可信后台和固定本机服务调用，配对令牌不会交给网页或内容脚本。新的消息契约必须限制来源、形状、批量、时间与取消，不允许消息指定 URL、索引、原答案或动作。关闭弹窗后继续、停止时取消和重启去重仍须实际 MV3 验收。

不会开放模型随意点击按钮。新增/保存仍消费原规划器能力，删除、附件、下一步和最终提交保持原边界。项目完成后再按相同方法扩展其他重复栏目和局部截图后备。
