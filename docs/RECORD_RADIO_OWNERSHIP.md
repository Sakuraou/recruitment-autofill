# 当前记录的原生单选选项归属

状态：planned。隔离绑定器探针已复现，尚未修复或通过完整验收。

## 复现与范围

先签发一个包含两个原生单选选项的当前编辑器快照，随后把第二个选项移到编辑器外。第一选项仍在原编辑器中，组名与原对象不变。绑定器返回 advanced，并点击、勾选外部选项一次。现有核验只检查组的第一个节点，成员属性指纹不能证明成员仍在当前编辑器内。

该证据来自内部绑定器与虚构 DOM。普通会话中另外制作的外部 form 关联夹具已在新增后停止；不能把内部探针直接当作真实网站或所有生产流程的复现。

## 要求

1. 整条预检时检查全部原生单选成员：原文档、原根、当前编辑器内、连接状态及唯一成员集合；任何外部成员都不能提供可写答案。选中的是内部选项，也不能因此放过同组的外部成员。
2. 各字段实际写入前复查当前编辑器及原列表归属。前一字段事件把单选成员移走时，不能继续点击后一个选项；不得等写完才阻止 Save。
3. 只在保存前发现选项被移走，也不得签发字段核验或保存回执。已接受的单选保持可见，不能点击另一项、reset 或直接改 checked 制造成功恢复。
4. 回滚只针对仍属于当前编辑器的原对象。外部或人工变更的对象不触碰，并准确报告恢复不完整。
5. 普通填写的原有调用兼容；新增内部执行检查不能由网页消息传入函数、选择器或个人值。模型没有归属判断或动作权限。

## 验证

先写失败测试：外部答案、选内部答案但同组另有外部成员、第一字段事件移走选项、选项事件移出自身、静默等待期间移出、重扫期间移出。断开、跨文档、影子根、原生 form 关联及原列表／编辑器移位分别覆盖；正常整组填写、原单选恢复契约、停止和动态展开保持。

再用隔离 Chromium 的真实原生 click 证明外部选项点击为零；实际生产流程遇到这类结构保留草稿、零 Save。完整 check 与 E2E 后更新验收记录，再补教育和项目的未标注标题身份核验，最后回到实习存在性／证明组及当前条模型。
