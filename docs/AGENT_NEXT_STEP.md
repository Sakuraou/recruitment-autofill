# Agent 下一步决策

状态：2026-10-05，I-011B已通过完整发布回归，v0.6.33可受控试用。

## 使用入口

先在项目目录运行 `npm run semantic:setup` 配置自己的兼容 API，再运行 `npm run semantic:serve`。密钥仅在本机配置，不要发送到聊天或写入档案 JSON。服务必须使用兼容接口；旧 Responses 服务不提供下一步决策。

扩展管理页重新加载 `dist` 后，保留网申草稿并刷新招聘网页；在「我的档案 → AI 识别连接」导入服务生成的配对文件，回到网页点「启动 Agent 连续填写」。运行期间保持弹窗打开，关闭会停止本次 Agent 及其已启动的栏目任务，已保存内容和网页草稿保留。原单栏连续填写入口仍按原方式在关闭弹窗后继续。

这一版只安排当前主页面提供的普通字段、教育、项目和实习任务；它不能自主探索任意按钮或跨页提交。已核验的记录跳过，未知问题暂留；奖项、论文、附件和不可访问区域保留待办。低置信度个人字段的模型确认仍留下一轮。完成提示限定当前可访问且支持的任务，不代表整份投递完成。

## 当前草稿

提供独立的下一步协议和 `/v1/next-step` 认证本机路由，复用用户明确配置的兼容模型。模型从本地执行器已核验的能力中选择一个：填写当前普通字段，或连续处理教育、项目、实习栏目。请求只包含当前可用任务的临时引用、类别和待办数量，不包含个人答案、学校/公司/项目名称、页面地址、选择器或脚本。

每次重新观察都产生新请求。决定执行前再次核验同一页面、原控件、档案和连接；执行器负责真实写入、全部经历的原顺序、逐条新增、动态问题及保存回读。模型不能通过“完成”跳过待填信息。当前栏目的任务完成后仍要观察其他栏目；不支持的字段、缺少事实或不确定保存结果保留未完成状态。

草稿的协议/编排41项、兼容提供方18项、本机HTTP服务17项、扩展侧通道12项、运行控制6项检查通过。原语义服务30项与本机配置6项回归也通过。随后补上只读记录核验12项，并将三个HTTP/DOM链路场景接入新核验；九文件145项整组通过，另页面运行令牌10项通过。类型和代码检查通过，仍未做生产MV3 Agent操作或真实云模型验收。

三个链路场景使用真实本机HTTP服务、虚构兼容模型及jsdom页面，调用原字段写入器和教育/项目记录控制器：个人字段后自动填写两段教育和两个不同项目；仍有奖励待办时报告未完成；模型等待期间Add节点被替换时零动作。此夹具中的页面桥接还没有合入扩展入口。只读记录核验逐条比较当前摘要与完整当前条资料，不依靠卡片数量相等；隐藏、替换、未关闭编辑器、资料冲突和身份不足保留待办。

这仍是受限任务决策，尚不能自主读懂任何陌生加号或下拉框。不能把“模型接口接通”写成“通用Agent已经完成”。
