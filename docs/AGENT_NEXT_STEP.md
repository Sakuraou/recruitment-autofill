## 如何使用

1. 在项目目录运行 `npm run semantic:setup`，填写自己的 OpenAI 兼容 API 地址、模型名和密钥。配置只保存在本机，不要把密钥放进档案 JSON 或聊天。
2. 运行 `npm run semantic:serve`，保持该进程运行。在「我的档案 → AI 识别连接」导入服务生成的配对文件。旧 Responses 配置不提供 Agent 下一步接口。
3. 在 Chrome/Edge 扩展管理页重新加载 `dist`，保存网页草稿后刷新招聘页面，然后点击「启动 Agent 连续填写」。
4. 运行期间保持弹窗打开。可在 Agent 面板点停止；关闭弹窗也会停止后续操作，已保存内容和网页草稿保留。

原来的单栏连续填写入口仍可在关闭弹窗后继续；它们与 Agent 共用页面互斥，不能同时写入。

## 目前能完成什么

Agent 重新观察页面，在当前能够核验的任务中安排下一步：填写普通字段，或处理教育、项目、实习、奖励、专业论著和校内职务列表。每条记录使用自己的本地资料，逐条添加、填写、回读、保存，再重新观察。教育按阶段从本科到硕士推进；重复启动按身份核验已有记录，不依靠卡片数量跳过。

模型收到任务引用、类别、数量或经过脱敏的字段元数据；答案从当前本地档案读取。模型不能生成脚本、选择器或直接点击按钮，也不能用“完成”跳过未完成的任务。

v0.6.34 增加本人弱标量确认，例如出生日期：本地已有明确含义和事实，模型也确认相同白名单路径后，才交给原填写器。普通文本的出生日期、联系人的生日、已取得最高学位等有冲突的字段仍保持待办。原生受支持日期控件不受这个文本限制。

若档案标注有项目、实习、奖励或论文，却没有具体记录，Agent 保留资料待办；明确没有经历也不能忽略网页已有记录或打开的草稿。

奖励使用每条独立资料，原生存在性题、干部题和答题后出现的描述重新核验再保存。干部身份必须在档案中明确保存，不能由职务或获奖推断；陌生奖励字段现在可在当前事务中询问模型；缺事实保持待办。

论文逐篇保留自己的日期、摘要、发表状态和作者排序；同名不同DOI独立比较，保存后重新核验。明确原生存在性题和状态联动的刊物字段可以继续处理。缺资料、未知字段或不确定保存保留待办；陌生论文字段现在可在当前篇的原事务中询问模型；模型不能提供答案、日期或选择论文。
