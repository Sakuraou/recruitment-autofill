# 弱语义字段的模型确认（I-010，planned）

状态：I-010A verified（v0.6.29），I-010B planned。生产弱标签模型确认尚未开放。

## 已观察到的缺口

当前条实习编辑器内，“工作单位名称”和“承担的工作内容”分别能匹配公司、工作描述，但分数为 0.82。它们被列为含义不确定，不能进入只识别未知字段的模型后备。因此模型已接入也未必能解除这类停顿。

同一探针中的“工作单位 / 项目名称”也返回唯一最高匹配和 0.82，证明唯一最高分不能说明问题只有一种含义。教育“就读学校名称”和项目“这个项目的名称”存在同类缺口。探针只用了虚构描述，不执行网页操作。

## 分轮安排

A：先建立纯本地资格判断，区分未知含义、可请求确认的弱匹配、必须保留待办的冲突。当前条事实必须有效且可按控件格式填写；主标签、ARIA 标签及表头各自证据一致，组合字段的不同含义在发送前拒绝。不得只提高匹配分数或把所有 ambiguous 当成未知。

B：把资格接入当前条私有上下文与模型请求。弱匹配只允许模型确认本地已检测到的同一固定路径；模型改成别的路径时整条预检失败。未知字段保留现有固定目录。答案仍从当前条本地资料读取，不允许模型给出答案、索引或操作。

C：在实际 MV3 中验证多条不同经历、联动后新增字段、已保存跳过、手改、停止、资料变化和其他栏目零操作。教育、项目和实习分别验收，不因一种栏目通过就全局放开。

## 必须保留的边界

- 已知字段缺事实、当前条答案缺失或格式不合适：不请求模型，不借另一条。
- 跨栏目主标签、组合问题、证明人、上传、身份认证、已取得状态和薪资换算：保留待办。
- 用户已有值、控件禁用、归属变化及事务过期：不覆盖或点击。
- 通用普通页面规则与旧协议格式不改变；允许确认必须来自有效的当前条私有上下文。
- 保持整条预检、有界动态重扫、回读与保存回执核验；不能为了部分能填就误报整条完成。
