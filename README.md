档案中的项目、实习、学生工作、奖励、论文、专利、证书和计算机技能可标记为“未确认 / 有 / 没有 / 不适用”，记录来源、确认与更新时间。普通的是/否选择题可根据已有经历或明确确认自动回答，选择“有”展开的新字段由动态重扫继续处理；空列表不会自动回答“否”。组合问题、协议、联系人问题和未知选项保持待办。与已有资料冲突的“没有”或“不适用”会拒绝保存并保留记录，旧 v1 档案无需补元数据即可导入。

教育、项目、实习和学生工作的结束时间可单独标记为进行中。网页有唯一的至今 / Present 等选项时才自动选择，日期控件没有至今能力时会说明缺口，不能改成今天。状态切换不删除原日期，冲突须核对；明确未确认的日期不会被其他匹配或中国移动固定日期流程绕过。旧档案的真实日期继续可用，空结束时间不会自动视为至今。

档案页可保存完整英文姓名、健康、婚姻、厘米身高、千克体重、求职岗位/城市/薪资及个人作品链接。英文名不会拆成名和姓，测量字段没有明确单位时不自动填，项目仓库地址只来自该项目。URL 只允许完整 http/https 地址，不接受脚本、文件、认证内容或控制字符。每次保存生成新的随机修订号，使旧计划失效；v1 旧数据保持兼容。

旧版本的功能、测试数量和验收边界统一保留在 [验收记录](VERIFICATION.md)，避免把历史版本误认为当前安装包。后续迭代顺序、执行提示词和动态调整规则见 [可迭代项目计划](PROJECT_PLAN.md)。

AI 在「我的档案 → AI 识别连接」导入本机服务生成的配对文件后启用；模型只提议字段含义，填写值从本地档案读取。普通 AI 一键入口先填规则字段，再识别未知字段；有实际写入进展后等待页面稳定、重扫并继续处理新字段，最多三轮 AI。关闭普通 AI 弹窗会取消本次操作。项目及教育连续入口由页面内任务逐条运行，每条当前编辑器最多三批未知字段，关闭弹窗仍继续；停止会取消后台请求。结果返回时复查原节点、页面、资料和连接，已认识但缺事实的字段不调用模型。普通 AI 入口的含义缓存最多保留十分钟、100 项，答案仍重新读取；项目及教育连续入口暂不共享该缓存。尚未接入其他通用重复栏目、跨重启缓存或截图。边界见 [语义模型契约](docs/SEMANTIC_MODEL.md)、[当前项目契约](docs/PROJECT_AI_BINDING.md)、[当前教育契约](docs/EDUCATION_AI_BINDING.md) 和 [缓存契约](docs/SEMANTIC_CACHE.md)，启动方式见 [安装指南](INSTALL.md)。

## 开发与构建

需要 Node.js **22.12.0 或更新版本**及 npm。在项目目录运行：

```powershell
npm ci
npm run check
```

`check` 依次执行 lint、TypeScript strict 类型检查、测试和构建。单独构建使用：

```powershell
npm run build
```

扩展安装目录是生成的 `dist/`。`npm run dev` 仅提供 Vite 开发页面，不能代替加载扩展后的权限、消息与 Content Script 验证。

需要复现浏览器端到端测试时：

```powershell
npx playwright install chromium
npm run test:e2e
```

该脚本启动临时隔离的测试浏览器和本机测试页，使用虚构资料和模拟模型，结束后关闭；不会连接日常浏览器、调用真实模型或访问真实招聘网站。它需要 4173 和 43127 端口空闲，运行前停止开发用伴随服务。Playwright 仅作为开发测试依赖，不进入扩展安装包，也不用于自动投递。

## 安装到 Chrome / Microsoft Edge

可从 [GitHub Releases](https://github.com/Sakuraou/recruitment-autofill/releases) 下载已构建的安装包，完整解压后加载其中包含 `manifest.json` 的文件夹。源码安装按以下步骤进行。

1. 完成构建。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 打开「开发者模式」，选择「加载已解压的扩展程序」。
4. 选择本项目的 **`dist` 文件夹**，然后将扩展固定到工具栏。
5. 点击扩展，打开档案管理页，填写自己的真实资料并保存。也可以先使用下方的虚构测试档案验收。

更新代码后重新构建，在扩展管理页点击刷新。若正在测试的网页还保留旧 Content Script，也请刷新该网页再扫描。浏览器内部页面（如扩展管理页）、应用商店及其他受限页面不能作为填表目标。

## 本地试用：导入 → 保存 → 扫描 → 填写

在项目目录启动测试页：

```powershell
npm run serve:example
```

打开 [本地测试表单](http://127.0.0.1:4173/test-form.html)。服务器只绑定 `127.0.0.1:4173`，只读取 `examples/` 中允许的静态文件，不接收表单上传。按 `Ctrl+C` 停止；端口占用时请先关闭占用该端口的进程。

1. 从测试页下载 [sample-profile.json](examples/sample-profile.json)。姓名为「测试同学」，手机号为不可用的 `00000000000`，邮箱使用 `example.invalid`；学校、项目、论文与家庭成员全部为虚构测试数据。
2. 在扩展档案管理页选择 JSON 导入，检查内容，**保存档案**。样例不会自动写入扩展，也不能用于真实投递。
3. 切回测试页，点击扩展的扫描按钮。
4. 检查每个字段的来源、档案路径、置信度和处理说明，再执行高置信度填写；待确认的候选应先核对。
5. 检查本科与硕士对应关系、学历与学位、已有值、验证码与未知问题。页面顶部提交计数应保持 **0**。
6. 点击「新增“民族”字段」后重新扫描。扫描后手工修改姓名，再执行旧扫描结果，验证已有值受到保护。
7. 如需验证测试页本身的拦截机制，可人工点击「人工测试提交拦截」；计数会增加，但不会发送表单。点击「重置测试表单」可恢复初始状态。

测试档案故意将硕士放在教育数组第一项、本科放在第二项，并省略 GPA 与专业类别。缺失信息应保持空白；「软件工程」不能直接被当作「计算机类」的已知事实。

## 日常使用

在真实招聘页面填写前，先维护完整、准确的档案。中国移动校招请先完成网站基础信息，再点击「补全整份简历」。启动即授权保存每条经历，最终投递仍由本人操作。中国移动日期只有月份时默认使用月初/月末约定，原档案不变，启动前可取消。其他网站可在出现试用入口时连续填写全部项目，其余栏目使用扫描及逐字段模式。通用项目试用按档案实际日期精度处理，不补造具体日；未知事实、证明、薪资仍需本人补齐。

已填写或禁用的控件会保留；空白且可识别的只读日期可以填写。执行一次「一键填写高置信度字段」后，扩展会等待网页联动并自动重扫，最多执行 4 轮，因此证件类型等选择后才出现的字段也能在同一次操作中继续处理。页面跳转、切换到下一步骤或更换档案后仍需重新扫描。第一次使用某个招聘网站时，请逐项核对。

通用逐字段模式支持主文档、同源 iframe 和开放 Shadow DOM 中的原生 `input`、`textarea`、单选 `select`、单选按钮组，以及带明确事实标签的原生/ARIA `checkbox`，并可从 `table`、`dl`、常见表单栅格及相邻标题提取标签。明确的“是/否”事实会沿用网页的原生事件链；已有勾选、无标签控件和协议、隐私、授权、承诺、声明类控件仍交给用户。中国移动连续模式额外支持教育/项目等多栏目新增、日历、下拉和保存核验。附件、验证码、身份认证与最终提交由用户处理；跨域 iframe、关闭的 Shadow DOM、画布控件和部分 Ant Design / Element Plus 深度定制组件仍需要站点适配。

带稳定 `aria-controls` / `aria-owns` 列表绑定的组合框，可自动打开菜单、等待唯一选项并选择；选项加载和选中回写各最多等待 500ms，随后整批复核答案是否保留。用户中途输入、节点替换、绑定变化、隐藏或禁用选项，以及多个选项同时选中都会停止该字段。隔离浏览器测试覆盖真实 React 异步下拉、重新渲染和同源 iframe 事件。

普通事实复选框还会核对不确定状态和网页校验错误，不能为了满足必选规则把档案中的“否”改成“是”。记录绑定器支持明确“否”的零操作核验和失败回滚；项目投影没有配置的布尔字段仍需人工。回滚会核对控件身份、保护用户的新答案，并检查原值真正恢复，不能恢复时停止保存。

原生单选按钮没有通用的“取消选择”操作。如果后续字段失败，记录引擎会保留刚才的选择并报告回滚不完整，停止保存；不会只改 DOM 后声称已恢复，也不会点击另一答案或重置整张表单。不同开放 Shadow DOM 中的同名单选题独立处理。

**中国移动校招页面：** 在 `job.10086.cn/personal/resume_campus.html` 支持多栏目连续流程，使用网站本身的加号、标签页、hover 下拉、学校目录、日历、单选和保存事件。已有同名、类型和日期的记录会跳过，未保存草稿受保护。保存回执不明时不会连续重试。证件类型、城市联动、附件、身份认证和最终投递仍需人工操作。操作说明见 [移动页面修复与 Edge 使用](MOBILE_FIX.md)。

逐字段模式中，置信度 ≥90% 的规则结果可批量填写；低于 90% 的候选先核对再确认。没有候选或超字数限制时保留人工填写。中国移动连续模式按整条档案创建记录，不需要逐项确认经历归属，并在结束时审计网页仍为空、选“否”或留有草稿的栏目。

Debug 展示 DOM 描述、档案路径、来源与置信度，复制时隐藏候选值和已知个人资料。岗位 JD 可手动粘贴或读取页面选中文本，仅作为当前弹窗备忘，关闭后清除；本版不使用它生成答案。

## 数据与权限边界

- `activeTab`：用户主动操作扩展时，临时访问当前标签页。扩展没有申请常驻所有网站访问权限。
- `scripting`：在用户选择扫描的页面注入 Content Script，用于读取和填写表单。
- `storage`：把档案与相关设置保存到当前浏览器配置中的 `chrome.storage.local`。
- `chrome.storage.local` **不是加密保险箱**。扩展未实现 Web Crypto 加密，设备或浏览器配置被他人访问时不能据此保证保密；卸载扩展也可能移除本地数据。
- JSON 导出备份包含档案原文，可能包括身份证、手机号、住址与家庭成员。请放在自己控制的位置，分享调试资料前检查并遮盖敏感信息。
- MVP 1 不调用 LLM，不把档案上传到开发者服务器；测试服务器也不接收个人资料。档案一旦被填入招聘网页，该网站就能读取这些值，并按自己的逻辑处理。
- 扩展不会主动点击投递／提交按钮，不调用表单提交，也不触发 Enter 操作。填写时为兼容网页会触发 `input` / `change`；**网站自己的事件处理可能保存数据或触发其他行为**。请留意网站提示。

## 第一版结构

```text
recruitment-autofill/
├── manifest.json              # Manifest V3 与最小权限
├── src/
│   ├── background/            # Service Worker
│   ├── content/               # DOM 扫描、字段执行与页面消息
│   ├── matching/              # 规则、中文别名与候选选项匹配
│   ├── profile/               # 档案 Schema 与本地存储
│   ├── popup/                 # 扫描、匹配预览、填写和调试
│   ├── options/               # 档案管理、JSON 导入导出
│   └── shared/                # 字段、匹配与消息类型
├── examples/                  # 原生中文测试表单、虚构样例档案
├── scripts/                   # 构建与仅本机测试服务器
├── tests/                     # 自动化测试
└── dist/                      # 构建后加载此目录
```

架构流程：用户在 Popup 发起操作 → Content Script 扫描页面并返回字段描述 → 规则匹配本地 Profile → 展示依据和置信度 → 经过执行检查后回填页面。低置信度、歧义和缺失事实不应被当作可靠自动填写结果。

完整 TypeScript 档案类型与运行时校验见 [src/profile/schema.ts](src/profile/schema.ts)，`FieldDescriptor`、`MatchResult` 和消息结构见 [src/shared/types.ts](src/shared/types.ts)。Profile 使用 `schemaVersion: 1`，结构包括：

| 部分 | 内容 |
| --- | --- |
| `basic` | 姓名、联系方式、出生日期、籍贯、生源地等 |
| `education[]` | 学校、专业、专业类别、`level` 学历、`degree` 学位、日期、成绩、研究方向、课程 |
| `research` | 研究方向、摘要、论文、专利 |
| `projects[]`、`internships[]`、`studentWork[]` | 多段项目、实习、学生工作 |
| `awards[]`、`certificates[]` | 奖项、证书 |
| `skills` | 编程语言、框架、工具和其他技能 |
| `commonAnswers` | 自我评价、个人优势、规划、动机、岗位匹配与研究／项目简介 |
| `family[]` | 家庭成员资料 |

`TextVariants` 支持 `short`、`medium`、`long` 和 `byLimit`，例如 `byLimit["50"]`、`byLimit["100"]`、`byLimit["200"]`、`byLimit["500"]`。这些是你自己保存的版本，MVP 1 不生成或扩写事实。缺少答案时请补充真实档案，不能通过编造测试数据解决。

## 验收清单与后续开发

本地夹具首次扫描 43 个字段：28 个高置信度、1 个待确认、2 个缺少资料、10 个需人工处理、2 个保留已有值。实际填写成功 28 项，专业类别只在显式确认后写入，提交事件计数为 0。动态添加民族字段后重扫成功填写；Content Script 读取完整档案被浏览器拒绝。另有 React 受控 input、textarea、select、radio、checkbox，异步原生 select 和记录字段回滚测试。自动化检查不等同于具体招聘网站的真实兼容性验证。

后续按照实际使用反馈推进：先完善 Generic 表单适配，再考虑结构化输出并校验的 LLM 字段匹配，最后加入需预览确认的开放题生成。不会因为引入 AI 而绕过事实约束、敏感数据保护或人工提交。

实现依据：[Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[Chrome Storage](https://developer.chrome.com/docs/extensions/reference/api/storage)、[Playwright 扩展测试](https://playwright.dev/docs/chrome-extensions)。
